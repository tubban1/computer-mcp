# Roadmap to AgentOS Runtime 1.0

Current baseline: **v1.0.0-rc.1**

The core execution Runtime is feature-complete enough to enter production-hardening mode. 1.0 should prioritize invariants, recovery, compatibility, and long-duration reliability over adding more feature surfaces.

**Architecture freeze for 1.x:** production remains a standalone Computer MCP release. OWL Runtime integration is development/test dogfood for a future major release and must not become a 1.x production dependency.

## 1. Production service baseline — DONE

- [x] compiled `dist` Runtime
- [x] immutable release directories
- [x] launchd supervision
- [x] production/development/test state isolation
- [x] health verification
- [x] install-time rollback with rollback health verification
- [x] active-release self-mutation guard

## 2. Session-aware concurrency baseline — DONE

- [x] execution context
- [x] action-scoped workspace Resource Arbiter locks
- [x] hierarchical parent/child conflicts
- [x] sibling workspace concurrency
- [x] Task-scoped durable ownership
- [x] Process-scoped durable ownership
- [x] Transaction-scoped durable ownership
- [x] persistent process metadata/logs
- [x] recovered/disconnected process claim
- [x] orphan session lease reclamation

## 3. Graceful drain / wait / takeover / handoff — v0.9.12 DONE

- [x] Runtime state: RUNNING → DRAINING
- [x] stop accepting new side-effecting work while draining
- [x] allow already-admitted Task work to finish its run boundary
- [x] Scheduler/Loop stop launching new work while draining
- [x] wait for active mutation scopes and managed write processes
- [x] `runtime.workspace wait`
- [x] explicit takeover request
- [x] explicit workspace handoff with ownership snapshot validation
- [x] durable handoff receipt
- [x] no silent lease stealing
- [ ] supervisor-level STOPPED/REPLACED state — belongs to upgrade protocol
- [ ] cross-Runtime Task migration/handoff — not required for basic workspace handoff

## 4. Upgrade protocol / graceful candidate cutover — v0.9.13 DONE

- [x] start candidate Runtime on alternate loopback port
- [x] candidate uses the same production state root
- [x] candidate starts DRAINING
- [x] candidate disables Scheduler/Loop/Process Monitor
- [x] validate candidate health/state compatibility before disturbing old Runtime
- [x] drain old Runtime through governed MCP `runtime.control`
- [x] wait for mutation/write-process safe boundary
- [x] switch `current` release
- [x] replace old process through launchd
- [x] verify post-cutover production health
- [x] automatic rollback to previous immutable release on cutover health failure
- [x] upgrade Runtime verifier
- [ ] zero-downtime traffic proxy/router — not required for 1.0

## 5. Durable state schema and migration — v0.9.14 BASELINE DONE

- [x] global Runtime state schema/version manifest
- [x] legacy unversioned state represented as schema 0
- [x] migration registry with stable IDs and ordered forward path
- [x] future/newer schema fails closed
- [x] `runtime.state status | plan | migrate`
- [x] migration requires DRAINING + explicit confirm
- [x] automatic migration requires auto-safe + rollback-compatible path
- [x] atomic manifest commit
- [x] crash journal and idempotent recovery
- [x] production candidate migrates only after old Runtime drains
- [x] documented code rollback vs state rollback rules
- [ ] backup/checkpoint protocol for future incompatible migrations
- [ ] per-store schema ownership

## 6. Recovery and fault-injection matrix — v0.9.15 DONE

- [x] crash during filesystem mutation — atomic temp/replace
- [x] crash during Git completion/rollback cleanup — durable receipt replay
- [x] crash/reconnect while managed process runs — durable process ownership + claim/reconcile
- [x] crash during scheduler wake — deterministic occurrence Task id
- [x] crash during loop phase — deterministic phase Task id
- [x] crash during browser-agent send — pending-send freeze/explicit resolution
- [x] crash during WeChat send — pending-send freeze/explicit resolution
- [x] crash during semantic promotion — existing memory + backlink repair
- [x] crash during workspace handoff/takeover — releasing/released/completed replay
- [x] durable state migration journal recovery
- [x] same-Runtime disconnected MCP session lease reclamation
- [x] focused `verify:fault-recovery`
- [x] aggregate `verify:recovery-matrix` release gate

- [ ] warm local MCP `read_file` P95 < 1.5 s

- [ ] local MCP session bootstrap < 3 s

- [ ] server-side MCP latency telemetry exposed in health
- [ ] 10 locally composable actions verified through one `computer_batch` round trip
- [ ] multi-second remote latency is diagnosable as server vs gateway/transport
- [ ] read-only filesystem observation is not blocked by unrelated workspace writers
- [ ] exact-path read/write resource conflicts remain enforced
- [ ] interactive MCP resource waits are cancellation-aware and bounded (default 3 s)
- [ ] cancelled resource waits leave no ghost queue entries
- [ ] natural managed-process exit converges to non-running state and releases workspace ownership
- [ ] `npm run verify:performance-p0` passes
- [ ] Streaming/incremental search is explicitly deferred to 1.x and is not a 1.0 blocker
