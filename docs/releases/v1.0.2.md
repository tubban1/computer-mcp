# Computer MCP 1.0.2

Computer MCP 1.0.2 closes the macOS permission-identity gap discovered during real ChatGPT/Tunnel dogfooding.

## What changed

- Adds a stable permission-bearing `Computer MCP Runtime.app` at `~/Applications/Computer MCP Runtime.app`.
- Freezes Runtime Host Bundle ID `fan.fde.computermcp.runtime` and independent Host version `1.0.0`.
- Packages the official Computer MCP icon into the Runtime Host app as a macOS `.icns` resource.
- Production launch uses the stable Runtime Host to supervise Node instead of treating Homebrew Node as the long-lived permission identity.
- Adds macOS filesystem preflight so protected-folder denial is detected in an isolated child probe before Node's libuv filesystem workers can become stuck.
- Keeps existing `Computer MCP Helper.app` independent for Accessibility and Screen Recording.

## One-time macOS permissions

The permission model is intentionally split:

- **Computer MCP Runtime** → Full Disk Access / protected user files.
- **Computer MCP Helper** → Accessibility + Screen & System Audio Recording.

Server 1.0.x releases do not replace either permission-bearing app during ordinary promotion.

## Evidence

The Runtime Host contract verifier freezes the Host path, Bundle ID, Host version, source fingerprint, icon inclusion, and Server/Host separation. Existing 1.0 concurrency, transport rotation, recovery, immutable release, Production boundary, and performance gates remain part of the release gate.

The 2h/6h/24h soak profiles remain available but are not claimed as completed evidence unless an observed run reports success.
